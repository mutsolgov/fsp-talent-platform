# Цифровая платформа-агрегатор ИТ-вакансий с верифицированным профилем достижений ФСП (ЛЦТ 2026)

Промышленная цифровая платформа обратного рекрутинга (модель LHH) с объективной верификацией квалификации ИТ-специалистов через калиброванную адаптивную тестовую батарею KITE IRT 3PL, генератор изоморфных заданий на базе HMAC-SHA256, сквозную защиту персональных данных по 152-ФЗ и интеграцию с реестром Федерации спортивного программирования (ФСП).

---

## 1. Архитектурные основы и ключевые механики

### 1.1. Модель обратного рекрутинга (Reverse-Recruiting / LHH)
- Кандидаты **не категоризируются** по самописным ключевым словам из резюме.
- **Категория = Специализация + Подтвержденный грейд**, присваивается строго по итогам обязательного онбординг-опроса и адаптивного тестирования KITE.
- Работодатель формулирует потребность команды (стек, грейд, обязательная вилка ЗП) и получает ранжированную подборку кандидатов с прозрачным обоснованием (**Explainability Match %**).
- Механизм сохранения подборки при уточнении фильтров гарантирует сохранение ранее найденных кандидатов (`is_pinned`, snapshot diff).

### 1.2. Равноправие кандидатов без истории ФСП (`fsp_id = null`)
- Платформа гарантирует **100% равные возможности** для специалистов без спортивного бэкграунда.
- При отсутствии спортивного профиля веса формулы ранжирования динамически переаллоцируются:
  $$S_{\text{non-fsp}} = 0.52 S_{\text{test}} + 0.30 S_{\text{stack}} + 0.00 S_{\text{fsp}} + 0.18 S_{\text{freshness}}$$
  вместо стандартной формулы с ФСП:
  $$S_{\text{fsp}} = 0.35 S_{\text{test}} + 0.25 S_{\text{stack}} + 0.25 S_{\text{fsp}} + 0.15 S_{\text{freshness}}$$
- Кандидат без спортивного профиля имеет математически равный шанс занять топ-1 в подборке работодателя.

### 1.3. Психометрический движок KITE IRT 3PL и защита от утечек (HMAC-SHA256)
- **3PL логистическая модель Бирнбаума** с байесовской оценкой способностей $\theta \in [0, 100]$ на основе калиброванных параметров заданий ($a$ — дискриминативность, $b$ — сложность, $c$ — угадывание).
- **Изоморфная генерация**: детерминированная мутация заданий через $\text{seed} = \text{HMAC-SHA256}(\text{candidate\_id}, \text{session\_id}, \text{item\_id})$. Генерируются уникальные условия, константы, входные данные и скрытые тесты при строго идентичной вычислительной и алгоритмической сложности.
- **Непринудительный грейдинг**:
  - $\theta < 70$: подтверждение текущего уровня без принудительного понижения с предложением пройти тест на грейд ниже;
  - $70 \le \theta < 88$: успешное подтверждение заявленного грейда;
  - $\theta \ge 88$: подтверждение грейда с предложением буст-теста на грейд выше.
- Кулдаун 90 дней на повторное изменение грейда с функцией мгновенного сброса для оценки жюри.

### 1.4. Защита персональных данных (152-ФЗ) и прозрачность зарплат
- Прямые контактные данные соискателя (`email`, `phone`, `telegram`, `github`, сырой PDF-файл) физически маскируются на уровне сериализатора бэкенда.
- Доступ к контактам открывается работодателю **только после явного согласия соискателя** (`status = 'accepted'` в приглашении или прямой отклик кандидата на вакансию).
- **Обязательная вилка ЗП в рублях**: каждое приглашение со стороны работодателя и каждая опубликованная вакансия обязаны содержать диапазон (`salary_min > 0 AND salary_max >= salary_min` со спредом $\le 3.5$), валидируемый ограничениями `CHECK` на уровне базы данных.

### 1.5. Интеграции, антифрод и брендированный PDF
- **ATS-интеграция**: экспорт кандидатов в форматах Huntflow и HeadHunter, доставка вебхуков с подписью HMAC-SHA256, окном защиты от повторов (replay window 300с), экспоненциальным бэкоффом и очередью недоставленных сообщений (DLQ).
- **Антифрод работодателей**: проверка корректности ИНН (10 и 12 цифр с контрольными суммами ФНС), валидация корпоративного домена, контроль аномальных зарплатных спредов.
- **Брендированный PDF-профиль ФСП**: 100% автономная генерация стандартизированного PDF-резюме (ReportLab) с использованием локальных шрифтов JetBrains Mono и брендбука ФСП (Dark/Light режимы).

## 2. Технологический стек

| Слой | Технологии | Назначение |
|---|---|---|
| **Backend** | Python 3.12, FastAPI, SQLAlchemy 2.0 (Async), Pydantic v2, PostgreSQL 16 / SQLite | Асинхронное REST API, ORM, строгая валидация контрактов |

| **Инфраструктура** | Docker, Docker Compose, Nginx (Alpine) | Воспроизводимый 100% автономный запуск без внешних платных сервисов |

## 3. Быстрый запуск

### 3.1. Запуск в Docker Compose (рекомендуемый способ)
```bash
docker compose up --build -d
```

После старта контейнеров платформа доступна по адресам:
- **Frontend SPA (интерфейс платформы):** [http://localhost](http://localhost) (порт 80)
- **Backend Swagger UI (документация API):** [http://localhost:8000/docs](http://localhost:8000/docs)
- **Телеметрия и операционные метрики:** [http://localhost:8000/api/v1/demo/metrics](http://localhost:8000/api/v1/demo/metrics)

Остановка контейнеров:
```bash
docker compose down
```

### 3.2. Локальный запуск для разработки

#### Бэкенд:
```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

#### Фронтенд:
```bash
cd frontend
npm install
npm run dev
```

## 5. Проверка качества и валидационные сьюты

Платформа снабжена комплексным набором автоматизированных тестов:

1. **Золотой бенчмарк ранжирования и IRT (900 пар, 6 метрик):**
   ```bash
   python3 tests/run_quality_gate.py
   ```
   *Контролируемые пороги*: Mean NDCG@5 $\ge 0.85$, NDCG@10 $\ge 0.88$, Precision@5 $\ge 0.80$, Reliability $r_{xx} \ge 0.85$, Kelley $D \ge 0.35$, Leak Resistance $\ge 0.85$.

2. **Сквозной контроль консистентности (17 проверок):**
   ```bash
   python3 scripts/check_consistency.py
   ```

3. **Сьют модульных и интеграционных тестов бэкенда:**
   ```bash
   PYTHONPATH=backend python3 -m pytest backend/tests/unit -v
   PYTHONPATH=backend python3 -m pytest backend/tests/integration -v
   ```

4. **Сборка и проверка целостности фронтенда:**
   ```bash
   npm --prefix frontend run build && node frontend/scripts/verify_build.js
   ```
