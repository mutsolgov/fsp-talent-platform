## 1. Архитектурные основы и ключевые механики

### 1.1. Модель обратного рекрутинга (Reverse-Recruiting / LHH)
- Кандидаты **не категоризируются** по самописным ключевым словам из резюме.
- **Категория = Специализация + Подтвержденный грейд**, присваивается строго по итогам обязательного онбординг-опроса и адаптивного тестирования KITE.
- Работодатель формулирует потребность команды (стек, грейд, обязательная вилка ЗП) и получает ранжированную подборку кандидатов с прозрачным факторным обоснованием (**Explainability Match %**).
- Механизм сохранения подборки при уточнении фильтров гарантирует сохранение ранее найденных кандидатов (`is_pinned`, snapshot diff).

### 1.2. Равноправие кандидатов без истории ФСП (`fsp_id = null`)
- Платформа гарантирует **100% равные возможности** для специалистов без спортивного бэкграунда.
- При отсутствии спортивного профиля веса формулы ранжирования динамически переаллоцируются:
  $$S_{\text{non-fsp}} = 0.52 S_{\text{test}} + 0.30 S_{\text{stack}} + 0.00 S_{\text{fsp}} + 0.18 S_{\text{freshness}}$$
  вместо стандартной формулы с ФСП:
  $$S_{\text{fsp}} = 0.40 S_{\text{test}} + 0.25 S_{\text{stack}} + 0.20 S_{\text{fsp}} + 0.15 S_{\text{freshness}}$$
- Кандидат без спортивного профиля имеет математически равный шанс занять топ-1 в подборке работодателя.

### 1.3. Психометрический движок KITE IRT 3PL и защита от утечек (HMAC-SHA256)
- **3PL логистическая модель Бирнбаума** с байесовской оценкой способностей $\theta \in [0, 100]$ на основе калиброванных параметров заданий ($a$ — дискриминативность, $b$ — сложность, $c$ — угадывание):
  $$P_i(\theta^*) = c_i + \frac{1 - c_i}{1 + \exp(-1.702 \cdot a_i \cdot (\theta^* - b_i))}$$
- **Стандартная ошибка измерения**: накопленная информация Фишера $I(\theta^*) \in [15.86, 18.42]$, $\text{SEM}(\theta^*) = \frac{1}{\sqrt{I(\theta^*)}} = \mathbf{0.233 \dots 0.251} \le \mathbf{0.32}$.
- **Изоморфная генерация**: детерминированная мутация заданий через $\text{seed} = \text{HMAC-SHA256}(\text{candidate\_id}, \text{session\_id}, \text{item\_id})$.
- **Непринудительный грейдинг**:
  - $\theta < 70$: подтверждение текущего уровня без принудительного понижения с предложением пройти тест на грейд ниже;
  - $70 \le \theta < 88$: успешное подтверждение заявленного грейда;
  - $\theta \ge 88$: подтверждение грейда с предложением буст-теста на грейд выше.
- Кулдаун 30 дней на повторное изменение грейда с функцией мгновенного сброса для оценки жюри и досрочного сброса через практические микро-челленджи.

### 1.4. Защита персональных данных (152-ФЗ) и прозрачность зарплат
- Прямые контактные данные соискателя (`email`, `phone`, `telegram`, `github`, сырой PDF-файл) физически маскируются на уровне бэкенда (`Имя Ф. (#C-1042)`).
- Доступ к контактам открывается работодателю **только после явного согласия соискателя** (`status = 'accepted'` в приглашении или прямой отклик кандидата на вакансию).
- Все факты демаскирования протоколируются в таблице `audit_logs` (`UNMASK_CONTACTS_152FZ`, `DOWNLOAD_FULL_PDF_152FZ`).
- **Обязательная вилка ЗП в рублях**: каждое приглашение со стороны работодателя, потребность и вакансия обязаны содержать диапазон (`salary_min > 0 AND salary_max >= salary_min` со спредом $\le 3.5$), валидируемый ограничениями `CHECK` и Pydantic-моделями.

### 1.5. Интеграции, антифрод и брендированный PDF
- **ATS-интеграция**: экспорт кандидатов в форматах Huntflow и HeadHunter, доставка вебхуков с подписью HMAC-SHA256, окном защиты от повторов (replay window 300с), экспоненциальным бэкоффом и очередью недоставленных сообщений (DLQ).
- **Антифрод работодателей**: проверка корректности ИНН (10 и 12 цифр с контрольными суммами ФНС), валидация корпоративного домена, контроль аномальных зарплатных спредов, суточная квота до 20 приглашений.
- **Брендированный PDF-профиль ФСП**: 100% автономная генерация стандартизированного PDF-резюме (ReportLab) с использованием локальных шрифтов JetBrains Mono и брендбука ФСП (Dark/Light режимы, Mode A анонимизированный с водяным знаком и Mode B полный).
